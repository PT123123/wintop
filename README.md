# WinTop Preview

Windows 下的桌面窗口预览工具：在桌面放若干个小"便签"窗，实时显示指定窗口的内容，支持刷新频率、颜色滤镜、暂停/继续等。

## 功能

- **程序入口**
  - 系统托盘图标（左键双击打开窗口选择器，右键菜单）
  - 桌面上可拖拽的悬浮图标（左键单击打开选择器，右键菜单），默认显示，可关闭并从托盘重新唤出
- **窗口选择器**：按标题/进程枚举可见窗口，选择后生成预览便签
- **预览便签**（右键菜单）
  - 刷新频率：1s / 5s / 10s / 30s / 60s
  - 滤镜颜色：无 / 红 / 绿 / 蓝 / 暖黄 / 灰度
  - 暂停 / 继续预览
  - 以管理员模式重启、关闭预览
- **停滞检测**：目标窗口失去响应时，预览标红提示"画面停滞"
- **最小化支持**：目标被最小化时，自动"无激活恢复→抓帧→再最小化"以拿到新画面（等待时长可调）
- **设置**（托盘 / 悬浮图标 → 设置）：最小化恢复抓帧等待时长，存注册表持久化

## 技术选型 / 框架

- **语言/平台**：C++20，纯 **Win32 原生 API**（不使用 Qt/WPF 等重框架），窗口小、常驻内存低。
- **构建**：**CMake** 生成 MSVC 工程；开发层面用 **just** 作为统一命令入口（见下）。
- **系统能力**：`dwmapi`（窗口枚举/缩略图）、`gdi32/user32`（窗口与绘图）、`msimg32`（`AlphaBlend` 半透明滤镜）、`shell32`（`ShellExecuteEx` 提权重启）。程序是 `WIN32` 子系统 gui 程序，无控制台。
- **提权**：普通权限运行；需要预览任务管理器等"高完整性"特权窗口时，可从菜单"以管理员模式重启"（`runas` 提权后退出当前实例）。

## 构建

### 依赖

- CMake ≥ 3.20
- MSVC（Visual Studio Build Tools / C++ 工作负载，含 Windows SDK）
- PowerShell（`just` 脚本的 shell）

### just 命令

```text
just build   # cmake 配置 + 编译 Release
just run     # build 之后启动程序
just clean   # 删除 build 目录
```

> `just run` 启动程序会占用 exe 句柄，此时再 `just clean` 可能因占用删除失败，属正常现象，先退出程序即可。

### 手动构建（等价于 just build）

```powershell
cmake -S . -B build
cmake --build build --config Release
# 产物: build/bin/Release/WinTopPreview.exe
```

## 获取窗口内容：方案演进

核心目标是"把某窗口画面抓出来显示在预览框里"。这个功能经历了多次取舍，这里记录**当前方案**和**被放弃过的方案**及原因。

### 当前方案（StickyNote.cpp）

- **可见/非最小化窗口**：每个刷新周期用 `PrintWindow(hwnd, dc, PW_RENDERFULLCONTENT)` 抓取目标**自身**内容（即使被遮挡也能取到目标内容），失败时回退到屏幕区域 `BitBlt`，得到一帧 `HBITMAP` 显示在预览框。
- **最小化窗口**：最小化窗口系统不渲染任何新帧。做法是 `ShowWindow(SW_SHOWNOACTIVATE)` 无激活恢复 → 等待可配置时长让窗口真正绘制 → 抓帧 → 再 `SW_MINIMIZE` 缩回去。代价是每次刷新目标会短暂闪现。
- **暂停**：停掉刷新定时器，画面冻结在已抓的上一帧。
- **滤镜**：`WM_PAINT` 中画面画完后用 `AlphaBlend`（`SourceConstantAlpha=70`）叠一层所选颜色，实现半透明滤镜。

### 被放弃的方案及原因

| 方案 | 做法 | 弃用原因 |
| --- | --- | --- |
| `GetDC(target)` + `BitBlt` | 抓目标窗口自己的 DC | 对 GPU/DirectX 渲染的窗口会抓到**黑屏**（DWM 合成窗口不把内容画在其窗口 DC 上） |
| `PrintWindow(PW_RENDERFULLCONTENT)` 独用 | 仅靠 PrintWindow 每帧驱动 | 对部分程序稳定返回同一张旧帧/失败，导致"怎么设刷新都不更新"，且最小化时无内容可抓 |
| 纯屏幕区域 `BitBlt` | 从屏幕 DC 按窗口坐标抓屏 | 窗口被完全遮挡时会取到"盖在上面的窗口"；且最小化窗口不在屏幕上，同样抓不到 |
| 最小化"恢复即抓即缩"衔接过短 | 恢复后立即抓取再最小化 | 窗口恢复后 DWM/应用来不及绘制，缩略抓画面仍是黑/旧帧（之前"仍黑色"的根因）——现改为**等待足够时长**后再抓 |
| `DwmRegisterThumbnail`（DWM 缩略图） | 用 API 生成实时窗口缩略图 | 对可见窗口流畅，但仍是依赖 DWM 合成：**最小化窗口不被合成** → 缩略图没有新内容；且状态切换（暂停/停滞）需要反复注册/注销，复杂不可控 |
| `Magnification API`（放大镜） | 系统放大镜窗口渲染源窗口 | 放大镜**只能放大（≥1×）**，不能把整个大窗口等比缩进小预览框，与"窗口缩略预览"需求冲突 |
| 独立子窗口叠加做滤镜 | 半透明覆盖子窗 | 子窗口的 `WS_EX_LAYERED` 半透明在部分场景不可靠/不显示，改回在 `WM_PAINT` 直渲 |

### 关于特权窗口（任务管理器）

任务管理器以**管理员（高完整性）**运行。中完整性进程无法捕获高完整性窗口内容（Windows 完整性级别隔离），所以普通权限下无法预览它。解决办法是从菜单**以管理员模式重启**本工具，使双方同权限即可预览。

## 已知限制

- 最小化窗口的"恢复→抓→最小化"会使其每次刷新闪现；等待时长可通过"设置"调节（默认 200ms）。
- 个别特权/受保护进程（即使同权限）可能仍无法捕获，取决于其窗口保护机制。
